# Diagnoza przed poprawką 0.5.3

AVD zachował osiem identycznych uchwytów tego samego vaultu z poprzednich odbiorów. Dawny limit sprawdzany przed otwarciem selektora blokował ponowne wskazanie tego folderu. Naprawa pozwala ponownie użyć istniejącego uchwytu tylko do odczytu; limit nowych uchwytów, identyfikatory wcześniejszych projektów i oddzielne uprawnienia eksportu pozostają zachowane.

Pierwsza regresja końcowego APK 21 października dała 3/6 PASS oraz osobno 1/1 PASS historii RPG. Zachowano pełny log i zrzuty w `final-regression-before-test-fix/`. Trzy błędy dotyczyły automatyzacji: chwilowego braku pola podczas przebudowy semantyki klawiatury, oczekiwania na przycisk wyboru folderu w niedozwolonym katalogu Download oraz odczytania statusu poprzedniej odpowiedzi podczas kolejnej generacji. Zrzut `memory-late-fact-answer.xml` potwierdza aktywny przycisk ponowienia po pierwszym COMPASS; późniejszy zrzut pokazuje trwające ponowienie. Test teraz czeka także na brak przycisku Stop i aktywne kontrolki następnego żądania. Ta nieudana regresja nie jest zaliczeniem importu ani trzech powtórzeń COMPASS. Nie stwierdzono na jej podstawie blokady strumienia w aplikacji.

Pierwsza próba Androida nie doszła do importu 2B: po wpisaniu hasha klawiatura zasłaniała przycisk, a gest testu trafiał w klawiaturę. Formularz otrzymał zamykanie klawiatury podczas przewijania; scenariusz jawnie ją chowa przed wyborem pliku.

Druga próba faktycznie wybrała GGUF, ale importer odrzucił go. Niezależny świeży JUnit zakończył się **36/37 PASS, 1 FAIL** (`importsRealOfficialTwoBWhenProvided`, `IOException: unsupported_model`, `GgufInspector.read:99`). Oficjalny plik 2B ma w metadanych nazwę `MiniCPM5 2.6B`, basename `MiniCPM5` i etykietę `2.6B`. Dawne `contains("2b")` po usunięciu interpunkcji nie rozpoznawało `26b`. Tabela tensorów mieści się w istniejących limitach.

Naprawa dodaje dokładny alias tych trzech pól i wymaga 42 warstw oraz embeddingu 2048. Wskazanie 2.6B przy niespójnych polach jest odrzucane przed starszym fallbackiem. Hash, architektura, kwantyzacje, granice i pozostałe limity nie zostały rozluźnione. Dwa nowe testy sprawdzają zgodny alias i odrzucenie wariantów niespójnych. Oddzielny test importuje cały rzeczywisty plik 2B z oficjalnym SHA-256.

Logi pierwszych prób są w katalogu nadrzędnym (`android-keyboard-before-fix-0.5.3.log`, `android-gguf-before-fix-0.5.3.log`, `android-junit-before-fix-0.5.3.log`). XML w tym katalogu przedstawia ekran po odrzuconym imporcie. Po nieudanym imporcie przerwano ręcznie pozostałe zależne scenariusze przez `am force-stop` własnej aplikacji testowej; końcowe `Process crashed` w tych dwóch logach oznacza to wymuszone przerwanie, nie rozpoznany crash silnika 2B. Częściowe wyniki tych prób nie są zaliczeniem regresji 2B.
